# All Metrics Keyword Planner

Работать только через MCP-инструменты плагина All Metrics. Не обращаться к Google Ads API напрямую, не запрашивать OAuth-токены и не изменять Keyword Plans, кампании, группы, объявления или ключевые слова.

## Найти источник и кабинет

1. Вызвать `list_sources` и убедиться, что доступен источник `google_keyword_planner`.
2. Вызвать `list_connections` с `source=google_keyword_planner` и выбрать подключение со статусом `connected`.
3. Вызвать `list_resources` с `source=google_keyword_planner`, выбранным `connection_id` и `selected_only=true`.
4. Передавать в `keyword_planner.resource_id` только внутренний `resources[].id`. Не подставлять `resources[].external_id`, который является Google Ads Customer ID.
5. Если подключений или Customer ID несколько и выбор не следует из запроса, показать подходящие варианты и задать один точный вопрос. Не выбирать первый кабинет молча.
6. Если источник виден, но инструмент `keyword_planner` не предоставлен плагином, сообщить, что схема инструментов All Metrics требует обновления. Не заменять его другим сервисом.

## Подтвердить язык и географию

Перед первым исследованием вызвать `keyword_planner` с `operation=options`, выбранными `connection_id`, `resource_id` и `execution=preview`.

При выборе страны повторять `operation=options` с `geo_query`. Использовать только подтверждённый `geo_results[].id`, у которого тип соответствует стране и статус допускает таргетинг. Не угадывать Geo Target Criterion ID и не принимать одноимённый город или регион за страну.

Для популярных предустановок языков и стран прочитать [targeting-presets.md](references/targeting-presets.md). Это названия для поиска и выбора, а не статические API-константы. Значения из `options` всегда важнее предустановок.

Критические ограничения:

- не использовать `1024` как казахский язык;
- не использовать `1035` как украинский язык;
- русский язык соответствует `1031`, украинский - `1036`;
- в текущем официальном таргетинге Google Ads отдельного казахского языка нет;
- если `options.languages` противоречит этим правилам, не выполнять запрос и сообщить о дефекте справочника All Metrics.

Если пользователь не указал язык или страну и их нельзя уверенно определить по сайту, ключевым словам или бренду, сначала собрать доступные варианты через `options`, затем уточнить выбор. Не смешивать данные разных языков или географий в одной строке результата.

## Выбрать операцию

- `generate_ideas` - найти новые ключевые слова по фразам, URL или всему сайту.
- `historical_metrics` - проверить готовый список, среднюю частотность, помесячную динамику, конкуренцию и ставки.
- `forecast` - оценить будущие показы, клики, CTR, CPC, расходы, конверсии, CR и CPA при заданных периоде и ставке.
- `ad_group_themes` - распределить ключевые слова по существующим группам Google Ads.
- `list_plans` и `get_plan` - прочитать существующие контейнеры Keyword Plans.

По умолчанию использовать `network=GOOGLE_SEARCH` и `include_adult_keywords=false`. Для короткого запроса использовать `execution=preview` с лимитом до 200 строк. Для полного исследования использовать `execution=background` и стабильный UUID v4 в `idempotency_key`; затем опрашивать `get_query_status` и получать все страницы через `get_query_results`. Вызывать `get_export_link` только по просьбе о CSV или JSON.

Не включать `force_refresh`, если пользователь прямо не запросил свежий пересчёт. Соблюдать максимум 10 географий и фактические лимиты, возвращённые `options`.

## Выполнить исследование

Базовый workflow:

1. Получить идеи через `generate_ideas`.
2. Удалить точные дубли и проверить `close_variants`, не складывая их автоматически как независимый спрос.
3. Запросить `historical_metrics` для отобранных фраз.
4. Проанализировать `monthly_search_volumes` и сезонность.
5. Выполнить собственную кластеризацию по теме и интенту, явно обозначив её как анализ AI, а не результат Google.
6. Для PPC-задачи выполнить `forecast`, указав период, ставку и допущения.
7. При наличии реальных Ad Group ID применить `ad_group_themes`.

Для `generate_ideas` использовать до 20 исходных фраз; при более длинном списке предложить `historical_metrics` или разбить исследование на логические пакеты. Для URL использовать только предоставленный или однозначно найденный сайт; `whole_site=true` применять только при явно выбранном домене.

## Интерпретировать показатели

- `avg_monthly_searches` - среднее число запросов для выбранных языка, географии, сети и периода, а не прогноз кликов и не число уникальных пользователей.
- `monthly_search_volumes` - помесячная история для анализа сезонности.
- `competition` и `competition_index` - конкуренция рекламодателей в платном поиске, а не SEO difficulty.
- `low_top_of_page_bid` и `high_top_of_page_bid` - границы ставки для верхней позиции.
- `impressions`, `clicks`, `cost`, `conversions` и производные forecast - прогноз, а не фактическая статистика кампании.

Не подписывать ставки, CPC, CPA или расходы как USD, EUR, KZT, BYN и другой валютой, пока ответ не содержит `currency_code`. При отсутствии валюты писать «в единицах валюты выбранного Google Ads аккаунта» и не сравнивать денежные показатели разных Customer ID.

Не считать нулевое значение доказательством отсутствия спроса без проверки языка, географии, сети и ответа Google. Не придумывать отсутствующие показатели и не заменять их отраслевыми оценками без явной маркировки.

## Подготовить ответ

По умолчанию дать:

1. Краткий вывод о спросе и практической ценности найденной семантики.
2. Таблицу ключевых слов с частотностью, сезонностью, рекламной конкуренцией и ставками.
3. Кластеры по теме и поисковому интенту.
4. Для PPC-задачи - отдельный прогноз показов, кликов, расходов, конверсий и CPA.
5. Язык, страну или регион, сеть и Google Ads Customer ID.
6. Ограничения данных, валюты, кеша и доступности production-операции.

Отделять данные Google от собственных выводов. Если пользователь просит фактические результаты действующей рекламы, использовать `analyze-all-metrics`. Если он просит одновременно оценить фактическую кампанию и найти новые ключи, сначала получить фактические данные через `analyze-all-metrics`, затем исследовать новые ключи этим skill и не объединять факт с прогнозом в одном показателе.

При HTTP 403 указать выбранные connection, resource и operation без секретов, сообщить о необходимости проверить доступ Customer ID и developer token. При 429 не спамить повторными вызовами. Не переключаться на другой кабинет или внешний источник данных без согласия пользователя.
