# All Metrics Diagnostics

Диагностический skill. Он выполняется первым, когда что-то не работает, и его результат — точный диагноз, а не предположение.

## Что диагностировать

Skill отвечает на пять вопросов в строгом порядке. Не переходить к следующему, пока предыдущий не получил фактический ответ.

1. Авторизован ли пользователь в MCP All Metrics.
2. Какая версия сервера All Metrics отвечает и совпадает ли она с ожиданиями плагина.
3. Какие инструменты реально доступны в этой сессии.
4. Какие источники подключены и в каком состоянии.
5. Какие ресурсы выбраны и пригодны для запросов.

## Шаг 1. Авторизация

1. Вызвать `get_current_user`.
2. Успешный ответ означает действующую OAuth-сессию со scope `mcp:use`.
3. Ошибка `auth_required` или `401` означает, что сессия не установлена или истекла. Сообщить пользователю, что нужно заново авторизовать коннектор All Metrics в клиенте, и не пытаться обойти авторизацию, подставить токен или запросить его у пользователя.
4. Не запрашивать у пользователя пароли, токены, коды авторизации и callback-ссылки.

## Шаг 2. Версия сервера и состав инструментов

1. Прочитать фактический список инструментов сессии.
2. Сверить его с эталоном из [compatibility.json](../../compatibility.json): `canonical.tools` и `mcp.baseline`.
3. Отчёт по расхождениям:

| Ситуация | Вывод |
| --- | --- |
| Все эталонные инструменты присутствуют | Сервер соответствует базовой линии плагина |
| Части эталонных инструментов нет | Сервер старше плагина; назвать недостающие имена и минимальную требуемую версию |
| Есть инструменты вне эталона | Сервер новее плагина; плагин безопасно работает, но новые возможности не описаны в skills |

4. Никогда не считать инструмент доступным на основании документации, названия skill или прошлой сессии.

## Шаг 3. Источники

1. Вызвать `list_sources`. Эталонный состав — двенадцать источников из `canonical.sources`.
2. Вызвать `list_connections` и для каждого источника зафиксировать статус подключения.
3. Разобрать типовые состояния:

| Состояние | Что означает | Что делать |
| --- | --- | --- |
| источник есть, подключения нет | Пользователь не подключал источник | Предложить подключить в интерфейсе All Metrics |
| подключение есть, требуется реавторизация | Токен истёк или не хватает scope провайдера | Назвать источник и нужный доступ, например `business.manage` для Google Business Profile |
| подключение есть, ресурсов нет | Ресурсы не обнаружены или не выбраны | Предложить выбрать ресурсы в интерфейсе All Metrics |
| источника нет в `list_sources` | Сервер старше плагина либо источник отключён на сервере | Назвать требуемую версию сервера |

## Шаг 4. Ресурсы

1. Вызвать `list_resources` с `selected_only=true` и `queryable_only=true`.
2. При наличии `get_resource_health` проверить состояние конкретного ресурса.
3. Отличать состояния:
   - `queryable` — ресурс пригоден для запросов;
   - не выбран — ресурс существует, но не включён пользователем;
   - `resource_disabled` — ресурс отключён; повторять запрос к нему запрещено;
   - временный таймаут доступности — ресурс остаётся зарегистрированным, это не удаление источника.
4. Для источника `website` использовать `website` с `operation=list`: эта операция возвращает сайты даже после временной ошибки доступности. Не выполнять принудительное обновление ресурсов ради проверки наличия сайта.

## Шаг 5. Разбор ошибок

| Код | Смысл | Допустимая реакция |
| --- | --- | --- |
| `auth_required` | Нет действующей сессии | Попросить авторизовать коннектор; повтор запрещён |
| `resource_disabled` | Ресурс отключён | Повтор и повторный выбор ресурса запрещены; предложить другой `queryable` ресурс |
| `retryable=true` | Временная ошибка | Один повтор, не больше |
| прочие `4xx` | Ошибка запроса | Исправить параметры по `list_fields`; слепой повтор запрещён |
| `5xx` | Ошибка сервера | Сообщить и не подменять данные оценками |
| пустой результат | Данных за период нет | Проверить период, ресурс, валюту и часовой пояс, прежде чем утверждать отсутствие активности |

Пустой ответ не является доказательством отсутствия рекламы, трафика или сделок, пока не подтверждены период и ресурс.

## Подготовить ответ

Дать компактный отчёт:

1. Авторизация: да или нет, и что делать при отказе.
2. Версия сервера и соответствие базовой линии плагина, с числом доступных инструментов против эталонных 80.
3. Таблица источников: источник, подключение, ресурсы, вывод.
4. Список конкретных блокирующих проблем в порядке их устранения.
5. Что именно уже работает и какие skills можно запускать прямо сейчас.

Не сообщать о работоспособности без фактического вызова инструмента. Любое утверждение отчёта должно опираться на конкретный ответ MCP.
