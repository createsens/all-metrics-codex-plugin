# Google Ads direct management via AllMetrics 3.9.0

Контракт: [compatibility.json](../../compatibility.json), skill `all-metrics-google-ads-management`. Для read-only аудита используйте соседний `all-metrics-ppc-audit`; этот skill не превращает обычный аудит в команду записи.

## Обнаружение и ограничения

1. Прочитать фактический MCP `tools/list`, вызвать `get_current_user` и проверить версию сервера 3.9.0+. Требуются `list_sources`, `list_connections`, `list_resources`, `google_ads_api_schema`, `google_ads_api_read`, `google_ads_write`, `google_ads_run_gaql`. Отсутствует любой обязательный инструмент - статус BLOCKED; не имитировать вызов через другой инструмент.
2. Использовать одно подключение и один link_id актёра на весь сценарий. Выбрать доступный владельцу Google Ads `connection_id` и queryable `resource_id` конкретного customer. MCC не равен client customer. Для direct-customer не передавать глобальный login-customer-id. Если цель неоднозначна, сначала уточнить - не выбирать аккаунт или кампанию наугад.
3. Проверить состояние через `google_ads_run_gaql` и/или `google_ads_settings`. Применять точные resource names, считывать существующие values, IDs, status и нужный updateMask, не выдумывать поля.
4. Вызвать `google_ads_api_schema` для метода Google Ads API v25 или v26. Follow `$ref` с аргументом schema для всех типов, enum и field masks. Каталог методов не гарантирует поддержку API/прав на конкретном аккаунте. Для операций GET, asynchronous status и batch pages допускается `google_ads_api_read`.

## Изменения

5. **Только явная команда пользователя на изменение** разрешает `google_ads_write`. Пользователь уже указал точные действия - не требовать отдельного AllMetrics grant, confirmation URL или prepare-этапа: в 3.9.0 Google Ads write прямой. Но не превращать просьбу про аудит, предложение или проверку в мутацию.
6. `google_ads_write` принимает `connection_id`, `resource_id`, `method`, `body`, необязательные `path_parameters` и обязательный `idempotency_key`. Customer ID получается из выбранного ресурса, не добавлять его в аргументы инструмента. Самостоятельно сформировать стабильный ключ уникальной операции, при повторе точно той же операции использовать тот же ключ; никогда не использовать один ключ для разных payloads.
7. Для сложных изменений, когда это поддерживает провайдер, сначала выполнить `validateOnly` (в JSON body) и обработать ошибки. Это **не** подтверждение и не обязательное разрешение AllMetrics. По умолчанию запись реальная и применяется немедленно, что может изменить показ рекламы. Не выполнять широкие или разрушительные изменения без явно соответствующего запроса пользователя.
8. Отправить точно согласованный payload, сохранить structured provider response, request_id, ошибки и partial failures. Если получен `outcome_unknown`, **не повторять** запрос автоматически: прочитать текущее состояние, определить неопределённые действия и сообщить о проблеме.
9. После успешного ответа повторно прочитать Google Ads через GAQL, settings или `google_ads_api_read` и сравнить все целевые поля. `validateOnly=200` не доказывает запись; response 200 без read-back - только provider acceptance. Не утверждать успех без проверки реального состояния.

## Результат

Показать аккаунт и затронутые объекты, исходное/ожидаемое/проверенное состояние, выполненные операции, частичные ошибки и уровень подтверждения LOCAL / PRODUCTION. Выводить только допустимые идентификаторы сущностей, не раскрывать OAuth токены, заголовки Authorization и другие секреты. Аналитические операции остаются read-only; отдельный approval workflow Localo сохраняется; GTM/Google tag с сервера 3.10.1 также работают без grants.
