# All Metrics PPC Audit

Работать только через read-only инструменты MCP All Metrics. Не изменять кампании, ставки, ключевые слова, объявления и подключения. Не выводить токены, секреты и персональные данные.

## Проверить совместимость перед работой

1. Прочитать фактический список инструментов текущей сессии MCP. Не предполагать наличие инструмента по названию skill или по документации.
2. Обязательные инструменты: `get_current_user`, `list_sources`, `list_connections`, `list_resources`, `list_setting_capabilities`. Минимальная версия сервера All Metrics — 3.2.0.
3. Если обязательный инструмент отсутствует, остановиться, назвать точное имя инструмента и требуемую версию сервера и предложить обновить All Metrics. Не заменять его другим сервисом и не придумывать данные.
4. Вызвать `list_setting_capabilities`, чтобы узнать, какие разделы настроек сервер реально отдаёт для каждой платформы. Аудит строить только по подтверждённым разделам.
5. Полный контракт требований — [compatibility.json](../../compatibility.json), раздел `skills["all-metrics-ppc-audit"]`. Методика проверок и их формулировки — [checklist.md](references/checklist.md).

## Определить объём аудита

1. Вызвать `list_sources` и `list_connections`. Аудит выполнять для тех платформ, где есть подключение со статусом `connected`.
2. Вызвать `list_resources` с `selected_only=true` и `queryable_only=true` для каждой платформы.
3. Для Google Ads при наличии `google_ads_list_customer_hierarchy` развернуть MCC и зафиксировать, какие Customer ID входят в аудит. Не смешивать разные Customer ID в одной строке итогов.
4. Для Яндекс Директа зафиксировать Client-Login выбранного подключения.
5. Если пользователь не ограничил платформу, проверять и Google Ads, и Яндекс Директ. Платформу без подключения помечать как `not_connected`, а не как «проблем не найдено».
6. Если подходящих кабинетов несколько и выбор не следует из запроса, показать варианты и задать один точный уточняющий вопрос.

## Зафиксировать период

- Если период не указан, использовать текущий календарный месяц с 1-го числа по сегодня и сравнивать с тем же числом дней предыдущего месяца.
- Использовать часовой пояс рекламного аккаунта. Указать его, если он влияет на границы периода.
- Для неполного текущего дня предупредить, что данные могут дозагружаться.
- Настройки читать на момент запроса, а статистику — за период. Не выдавать текущую настройку за настройку, действовавшую в прошлом периоде.

## Собрать конфигурацию

Предпочтительный путь — снимок настроек, если сервер его поддерживает:

1. `start_settings_snapshot` для выбранной платформы и ресурса.
2. `get_settings_snapshot_status` до терминального статуса.
3. `get_settings_snapshot_results` постранично до конца.
4. `analyze_settings_snapshot` для структурированных находок.
5. `get_settings_snapshot_export_link` — только если пользователь просит выгрузку.

Если снимок недоступен, собирать конфигурацию точечными инструментами.

Google Ads:

- `google_ads_list_campaigns` и `google_ads_get_campaign_by_id` — кампании, статусы, бюджеты, типы.
- `google_ads_settings` — доступные разделы настроек.
- `google_ads_run_gaql` — произвольные срезы; перед выполнением проверять запрос через `google_ads_validate_gaql`.
- `google_ads_change_history` — кто и что менял; `include_performance=true` даёт датированное сопоставление без утверждения причинности.

Яндекс Директ:

- `yandex_direct_get_campaign_snapshot` — полная конфигурация кампании одним вызовом; это предпочтительный первый шаг.
- `yandex_direct_audit_campaign` — структурированные находки по кампании.
- `yandex_direct_audit_tracking` — счётчики, цели, разметка и передача конверсий.
- `yandex_direct_audit_keyword_conflicts` — пересечения ключевых и минус-слов.
- Точечные инструменты: `yandex_direct_get_campaign_settings`, `yandex_direct_get_campaign_strategy`, `yandex_direct_get_geo_settings`, `yandex_direct_get_time_targeting`, `yandex_direct_get_keywords`, `yandex_direct_get_negative_keywords`, `yandex_direct_get_autotargeting`, `yandex_direct_get_bid_modifiers`, `yandex_direct_get_bids`, `yandex_direct_get_ads`, `yandex_direct_get_sitelinks`, `yandex_direct_get_ad_extensions`, `yandex_direct_get_retargeting`, `yandex_direct_get_audience_targets`, `yandex_direct_get_campaign_goals`.
- `yandex_direct_list_campaign_changes`, `yandex_direct_check_changes` и `yandex_direct_diff_campaign` — история и различия.

Критическое правило Яндекс Директа: `OFF` и `API_DOES_NOT_EXPOSE` — разные состояния. Настройку, которую API не отдаёт, нельзя описывать как выключенную.

## Собрать эффективность

1. Google Ads: `google_ads_run_gaql` или общий путь `list_fields` → `start_query` → `get_query_status` → `get_query_results`.
2. Яндекс Директ: `yandex_direct_report`, а также `yandex_direct_keyword_performance` и `yandex_direct_ad_performance` для срезов по ключам и объявлениям.
3. Поисковые запросы: `yandex_direct_get_search_queries` и GAQL-срез `search_term_view` для Google Ads.
4. Минимальный набор метрик: показы, клики, расходы с валютой, CTR, CPC, конверсии, CPA рекламной системы.
5. Не суммировать разные валюты. Конвертировать только при явном курсе и дате курса.

## Выполнить проверки

Выполнить блоки проверок из [checklist.md](references/checklist.md):

1. Структура аккаунта и кампаний.
2. Стратегии, бюджеты и ставки.
3. География и расписание показов.
4. Ключевые слова, соответствия, автотаргетинг и минус-слова.
5. Поисковые запросы и мусорный трафик.
6. Объявления, расширения и посадочные страницы.
7. Аудитории, ретаргетинг и корректировки ставок.
8. Отслеживание конверсий, разметка и связка с аналитикой.
9. История изменений и её сопоставление с динамикой показателей.

Каждая находка обязана содержать: платформу, кабинет, кампанию или сущность, наблюдаемое значение, чем именно оно подтверждено (инструмент и поле), оценку влияния и конкретное действие. Находка без структурированного подтверждения не включается в отчёт.

## Рассчитать показатели

- `CTR = клики / показы × 100%`
- `CPC = расходы / клики`
- `CPA рекламы = расходы / конверсии рекламной системы`
- Доля расходов на кампанию, группу или запрос = расходы сущности / общие расходы × 100%
- Доля показов по автотаргетингу и широкому соответствию считать отдельно от точного и фразового.

При нулевом знаменателе выводить `н/д`, а не ноль. CPL, CPS, ROAS и ROI в этом skill не рассчитывать: они требуют CRM-атрибуции и относятся к `all-metrics-cross-source-report`.

## Подготовить ответ

По умолчанию дать:

1. Краткий вывод: состояние кабинета, три самые дорогие проблемы и оценка потерь бюджета, если она подтверждается данными.
2. Таблицу находок с приоритетом `P0`, `P1`, `P2`, платформой, сущностью, подтверждением и действием.
3. Разбор по блокам проверок с отметкой `ok`, `issue`, `not_available` или `not_connected` для каждого.
4. Таблицу эффективности за период и сопоставимый прошлый период.
5. Сопоставление истории изменений с динамикой, явно помеченное как корреляция, а не причинность.
6. План работ по приоритету с ожидаемым эффектом и признаком, по которому эффект будет проверен.
7. Ограничения: какие разделы API не отдаёт, где данные неполные, где нужна реавторизация.

Отделять факты от выводов. Не выдавать `API_DOES_NOT_EXPOSE` за корректную настройку и не выдавать отсутствие данных за отсутствие проблемы. Для новой семантики и прогнозов передавать работу в `all-metrics-keyword-planner`, для сквозной экономики — в `all-metrics-cross-source-report`.
