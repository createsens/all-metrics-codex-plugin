# Яндекс Wordstat

Контракт возможностей: [compatibility.json](../../compatibility.json),
раздел `skills["all-metrics-wordstat"]`.

Работать через read-only MCP All Metrics. Ключ Yandex Cloud уже хранится на
сервере: не запрашивать, не передавать и не выводить секрет провайдера.

## Подключение и стоимость

Проверить реальные инструменты сессии и `get_current_user`, затем
`list_sources`, `list_connections` и `list_resources` для `yandex_wordstat`.
Нужны connected connection и queryable resource того же владельца. Использовать
внутренний `resource_id`, не Folder ID из `external_id`. При нескольких
подходящих подключениях уточнить выбор, не брать первое произвольно.

Нужны инструмент `yandex_wordstat` и сервер 3.3.0+ для расширенного контракта.
Если инструмент/параметры отсутствуют, назвать недоступную возможность и
предложить обновить каталог инструментов клиента. Не выдавать mock/расчёт за API.

`regions_tree` бесплатен. `top` и `dynamics` обычно стоят 0,02 ₽/вызов,
`regions` — 0,05 ₽/вызов; тариф уточнять в Yandex Cloud. До большого сбора
обозначить число вызовов и оценку, получить согласие на расход, если исходный
запрос его не задаёт. Не начинать рекурсивное расширение сотен seeds без лимита.
Кэш статистики — час; не включать `force_refresh` без необходимости/согласия.

## Собрать данные

Согласовать seeds, географию, устройства и требуемые методы. Сохранить каждую
введённую фразу, включая кавычки и операторы; не создавать quoted/broad варианты
самостоятельно. Удалить только внешние пробелы и полностью одинаковые строки.

- `operation=regions_tree` — подобрать числовые ID по названиям. `149` — Беларусь.
- `operation=top`, `top_kind=both|popular|similar`, `num_phrases=1..2000`:
  популярные и похожие приходят одним API-вызовом. `regions` — до 100 ID-строк;
  пустой список означает весь мир, несколько ID — объединённый спрос.
- `operation=dynamics`: `PERIOD_DAILY|PERIOD_WEEKLY|PERIOD_MONTHLY`,
  `date_range.start/end` в YYYY-MM-DD, тот же регион и устройства. Только `+`
  поддерживается в динамике; кавычки не дают точную частотность. Не удалять
  операторы самовольно, обозначить ограничение или согласовать другую seed.
- `operation=regions`: `region_type=REGION_ALL|REGION_CITIES|REGION_REGIONS`.
  Это мировое распределение; параметр `regions` сюда не передавать.

Устройства: `DEVICE_ALL` отдельно либо до трёх из `DEVICE_DESKTOP`,
`DEVICE_PHONE`, `DEVICE_TABLET`. Для полного ответа указать `limit=100000`,
не использовать preview. Не передавать настройки одного метода в другой.
Ошибки дат/доступа/квот исправлять по ответу API, не повторять бесконечно.

## Результат для семантики

Сохранить datasets с seed, методом, фактическим targeting, временем получения,
query_id, строками и meta/warnings/cache/billable. Для ключей сделать уникальный
список phrase с отдельными observations по seed и kind. Частоты перекрывающихся
фраз не складывать. Кавычки фиксируют количество слов, не буквальное совпадение.
Пустой ответ и достигнутый provider limit — предупреждения, не «спроса нет»
или «ядро полностью собрано». Отделить API-факты от предложенной кластеризации,
минус-фраз и SEO/рекламных рекомендаций. Рекомендации по включению ключей не
означают разрешение менять кампании.

Для ручного списка и JSON/CSV использовать [Wordstat в All Metrics](https://test.abeslab.by/hub/wordstat).
