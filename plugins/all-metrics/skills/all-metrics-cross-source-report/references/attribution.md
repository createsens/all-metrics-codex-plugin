# Атрибуция и сведение источников

## Ограничения Bitrix24

- Анализировать только сделки воронки «Онлайн заявки» с `CATEGORY_ID = 6`. Сделки других воронок игнорировать полностью.
- Заявка — уникальная сделка по ID, созданная внутри анализируемого периода.
- Продажа — сделка со статусом `WON`, закрытая внутри анализируемого периода. Сделка может быть создана в одном периоде, а закрыта в другом; это нужно указывать явно.
- Выручка берётся из `OPPORTUNITY` с учётом валюты сделки.
- Контакты запрашиваются только связанные с отобранными сделками и используются для дедупликации. Контакт не является заявкой. Персональные данные не выводятся.

## Признание сделки атрибутированной

Сделка считается атрибутированной к каналу только при наличии фактического идентификатора:

| Идентификатор | Канал |
| --- | --- |
| `gclid` | Google Ads |
| `yclid` | Яндекс Директ |
| `utm_source` + `utm_medium` | канал по разметке |
| идентификатор звонка CallRail | звонковый канал источника, зафиксированного CallRail |

Правила:

- Неатрибутированные сделки не распределять между каналами пропорционально, по правдоподобию или по историческим долям.
- Если сделке соответствует несколько идентификаторов, применять одну явно названную модель и указать её в отчёте.
- Всегда показывать три числа: атрибутированные сделки, неатрибутированные сделки, всего. И долю полноты атрибуции.
- Если полнота атрибуции ниже 60%, канальные CPL, CPS, ROAS и ROI помечать как оценочные и не использовать для решений о перераспределении бюджета без оговорки.

## Дедупликация

1. Дубли сделок — по ID сделки, затем по связке контакт + период + источник.
2. Звонок CallRail и заявка с сайта от одного человека в течение одного визита — одно обращение, а не два.
3. Конверсия рекламной системы и сделка CRM — разные сущности. Никогда не складывать их в один показатель.

## Ожидаемые расхождения между источниками

| Пара источников | Типичное расхождение | Причина |
| --- | --- | --- |
| Клики рекламы против сеансов аналитики | 5-15% | Отказ от загрузки, блокировщики, редиректы, разные окна сессии |
| Конверсии рекламы против целей аналитики | 10-30% | Разные модели и окна атрибуции |
| Цели аналитики против сделок CRM | 20-50% | Спам, дубли, обработка менеджерами, офлайн-обращения |
| Показы Search Console против сеансов | значительные | Показ в выдаче не равен визиту |
| Локальные показы GBP против рекламных показов | несопоставимы | Разные сущности, нельзя складывать |

Расхождение выше типичного — находка, требующая объяснения, а не повод подогнать цифры.

## Запрещённые операции со сводными данными

- Складывать суммы в разных валютах без явного курса и его даты.
- Складывать показы разных систем в «общий охват».
- Складывать конверсии рекламных систем с заявками CRM.
- Считать средний CPL по каналам как среднее арифметическое канальных CPL вместо `общие расходы / общие заявки`.
- Сравнивать денежные показатели разных рекламных аккаунтов без подтверждённой валюты каждого.
- Заполнять отсутствующие значения отраслевыми бенчмарками без явной пометки, что это не данные клиента.
